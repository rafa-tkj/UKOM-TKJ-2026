INFORMASI TABEL DHCP SERVER NETWORK (PENTING - HASIL TROUBLESHOOTING)
DNS pada tab DHCP Server > Networks bukan diisi 8.8.8.8 atau 127.0.0.1.
Isi DNS dengan IP interface MikroTik pada jaringan masing-masing, agar
client bertanya ke MikroTik. MikroTik kemudian meneruskan query internet
ke DNS upstream dan menjawab domain UKOM dari DNS Static.

Jaringan / Interface | Network | Gateway | DNS yang dibagikan ke client
ETH 2 SERVER | 10.10.20.0/28 | 10.10.20.1 | 10.10.20.1
ETH 3 CLIENT | 100.100.20.0/30 | 100.100.20.1 | 100.100.20.1
WLAN 1 HOTSPOT | 192.168.20.0/24 | 192.168.20.1 | 192.168.20.1

Catatan:
- Tabel berlaku jika jaringan tersebut memang memakai DHCP Server.
- Ubuntu Server tetap memakai IP statis 10.10.20.2/28.
- DNS lokal Ubuntu/BIND9 adalah 127.0.0.1; bukan DNS yang dibagikan
  kepada HP melalui DHCP.
- DNS global MikroTik boleh memakai upstream 8.8.8.8. HP tetap menerima
  DNS MikroTik, yaitu 192.168.20.1 pada jaringan hotspot.
- Pemeriksaan terakhir /ip dns menunjukkan servers=8.8.8.8 dan
  allow-remote-requests=yes. Pertahankan selama berfungsi.

Contoh record DNS Static MikroTik yang diperlukan:
/ip dns static add name=ukom12tkj-20.sch.id address=10.10.20.2 ttl=1d
/ip dns static add name=www.ukom12tkj-20.sch.id address=10.10.20.2 ttl=1d
Jangan jalankan perintah add berulang kali jika record sudah ada.
Periksa record dengan: /ip dns static print
Periksa DHCP Network dengan: /ip dhcp-server network print detail
Setelah mengubah DHCP Network, putuskan lalu sambungkan kembali Wi-Fi
atau perbarui lease client supaya client menerima DNS yang baru.

DHCP hotspot sebelumnya pernah terlihat INVALID dengan pesan
"Interface not running". Jangan membuat DHCP server kedua atau mengubah
interface sebelum memeriksa status wireless dan DHCP terkini.
Pastikan hanya ada satu DHCP server untuk jaringan hotspot.
Pool hotspot yang pernah terlihat: 192.168.20.2-192.168.20.254.

Hotspot sebelumnya terlihat menggunakan:
Interface : WLAN 1 HOTSPOT
Pool      : hs-pool-7
Profile   : hsprof1

Jangan membuat bridge baru jika rancangan tetap menggunakan WLAN
langsung sebagai interface hotspot.

Firewall:
- Jika chain forward tidak memiliki aturan drop yang memblokir trafik,
  tidak perlu menambah aturan allow yang sama berulang kali.
- Jika ada aturan drop, aturan allow dari 192.168.20.0/24 ke
  10.10.20.2 TCP port 80 harus berada sebelum aturan drop terkait.
- Untuk DNS, HP mengakses MikroTik di 192.168.20.1 port 53.
- Jangan menghapus dynamic Hotspot firewall rules.
- NAT internet yang diperlukan adalah masquerade menuju interface WAN
  ETH 1ISP. Pastikan aturan yang ada sudah bekerja sebelum menambah lagi.

- Sambungkan ulang Wi-Fi HP; pastikan IP 192.168.20.x, gateway dan DNS
  192.168.20.1. Periksa Private DNS HP jika masih gagal.
- Tes dari MikroTik: :put [:resolve ukom12tkj-20.sch.id]
  Hasil yang diharapkan: 10.10.20.2.

Jika muncul ERR_CONNECTION_REFUSED:
- Domain sudah diterjemahkan, tetapi koneksi HTTP ke server ditolak.
  Ini berbeda dari masalah DNS.
- Tes dari HP melalui Wi-Fi yang sama: http://10.10.20.2/
- Jika IP juga ditolak, periksa Apache dan port 80 di Ubuntu:
  sudo systemctl is-active apache2
  sudo ss -lntp | grep ':80'
  curl -I http://127.0.0.1/
  curl -I http://10.10.20.2/
- Jika tes lokal di Ubuntu berhasil tetapi HP tetap ditolak, periksa
  firewall MikroTik chain forward dari 192.168.20.0/24 ke 10.10.20.2
  TCP port 80, serta UFW Ubuntu.
- Jangan menambah aturan firewall secara membabi buta; periksa urutan
  aturan drop dan allow terlebih dahulu.
- Gunakan http://, bukan https://, jika HTTPS belum dikonfigurasi.

Jika alamat IP langsung bisa dibuka tetapi domain tidak:
- Periksa DNS Static MikroTik dan DNS yang diterima HP dari DHCP.
- Pastikan domain yang diketik tepat dan gunakan http://.

Jika IP langsung dan domain sama-sama loading:
- Periksa Apache aktif.
- Periksa port TCP 80.
- Periksa firewall MikroTik chain forward.
- Periksa log Apache:
  sudo tail -n 50 /var/log/apache2/ukom20-error.log
  sudo tail -n 50 /var/log/apache2/ukom20-access.log

D. Speed test:
Pengujian akses halaman HTML lokal berbeda dengan speed test internet.
Setelah akses lokal berhasil, uji internet HP dengan aplikasi/situs
speed test. Jika halaman lokal berhasil tetapi speed test gagal, periksa
koneksi internet, DNS, dan NAT secara terpisah.

10. FIREWALL UBUNTU (UFW) - JANGAN AKTIFKAN SEMBARANGAN
============================================================

Periksa dahulu:

sudo ufw status verbose

Jika UFW inactive, tidak perlu mengaktifkannya hanya untuk mengikuti
catatan. Jika UFW active dan akses layanan diblokir, izinkan layanan
untuk jaringan lab berikut:

sudo ufw allow from 10.10.20.0/28 to 10.10.20.2 port 53 proto udp
sudo ufw allow from 10.10.20.0/28 to 10.10.20.2 port 53 proto tcp
sudo ufw allow from 192.168.20.0/24 to 10.10.20.2 port 53 proto udp
sudo ufw allow from 192.168.20.0/24 to 10.10.20.2 port 53 proto tcp
sudo ufw allow from 10.10.20.0/28 to 10.10.20.2 port 80 proto tcp
sudo ufw allow from 192.168.20.0/24 to 10.10.20.2 port 80 proto tcp

Port 443 hanya diperlukan jika HTTPS benar-benar dikonfigurasi.
Jangan mengaktifkan UFW melalui SSH sebelum aturan SSH dipastikan aman.

12. BAGIAN LAMA YANG DIHAPUS / DIKOREKSI
============================================================

1. Menghapus CREATE DATABASE ukom20 yang tertulis dua kali.
2. Memperbaiki typo "ssudo systemctl restart apache2" menjadi
   "sudo systemctl restart apache2".
3. Menghapus IP hosts lama 172.16.0.178; IP server sekarang 10.10.20.2.
4. Menghapus IP/domain contoh dari topologi lain:
   192.168.8.197, 10.10.32.13, dan 192.168.137.3.
5. Mengoreksi DNS zone agar domain .20 mengarah ke 10.10.20.2.
6. Mengoreksi netplan agar nama interface enp0s3 dan indentasi YAML
   benar, dengan gateway 10.10.20.1 tanpa /28.
7. Menandai konfigurasi MikroTik bridge lama sebagai referensi usang,
   karena pemeriksaan terakhir menunjukkan Hotspot langsung pada
   WLAN 1 HOTSPOT dan bridge tidak ada.
8. Tidak menyarankan import konfigurasi MikroTik lama secara penuh,
   karena nama interface dan susunan aktual router sudah berbeda.
9. Menambahkan pemeriksaan DHCP hotspot INVALID, DNS HP, port HTTP,
   akses HTML dari HP, dan pengujian berdasarkan IP sebelum domain.
10. Menghindari penambahan firewall/NAT duplikat tanpa memeriksa
    aturan yang sudah aktif.
11. Menambahkan user MariaDB kedua ukom20-rafa untuk login phpMyAdmin;
    user aplikasi ukom20 pada database.php tetap dipertahankan.
12. Memperbaiki kasus login phpMyAdmin yang ditolak karena user
    ukom20-rafa belum terdaftar; user dibuat dan diberi hak SELECT.
13. Memisahkan hak Admin (ALL PRIVILEGES) dan Guest (SELECT) pada
    MariaDB, serta menegaskan bahwa role fitur website tetap diatur PHP.
14. Menambahkan tabel DNS DHCP Network untuk ETH 2 SERVER, ETH 3 CLIENT,
    dan WLAN 1 HOTSPOT. DNS client diarahkan ke IP MikroTik pada subnetnya.
15. Menambahkan troubleshooting NXDOMAIN dan ERR_CONNECTION_REFUSED,
    termasuk DNS Static MikroTik, allow-remote-requests, pembaruan DHCP,
    uji resolve domain, Apache/port 80, dan firewall forward.
