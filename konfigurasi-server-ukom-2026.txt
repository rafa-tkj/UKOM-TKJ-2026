Pilihan yang digunakan pada instalasi ini:
- Switch to unix_socket authentication: Y
- Change root password: N
- Remove anonymous users: Y
- Disallow root login remotely: Y
- Remove test database: Y
- Reload privilege tables: Y

Jalankan SQL berikut satu kali. Jangan membuat database yang sama
berulang kali:

IDENTIFIED BY 'GANTI_PASSWORD_DATABASE';

IDENTIFIED BY 'GANTI_PASSWORD_DATABASE';

GRANT ALL PRIVILEGES ON ukom20.* TO 'ukom20'@'localhost';
FLUSH PRIVILEGES;

USE ukom20;

Buat tabel jika belum ada:

6. DNS BIND9 DI UBUNTU SERVER
============================================================

Install/aktifkan:

sudo apt install bind9 bind9-utils bind9-dnsutils -y
sudo systemctl enable --now named

Zona domain:

sudo nano /etc/bind/named.conf.local

Pastikan ada satu deklarasi zona berikut (jangan diduplikasi):

zone "ukom12tkj-20.sch.id" {
    type master;
    file "/etc/bind/db.ukom12tkj-20.sch.id";
};

Buat file zona:

sudo nano /etc/bind/db.ukom12tkj-20.sch.id

Isi:

$TTL 604800
@   IN  SOA ns1.ukom12tkj-20.sch.id. admin.ukom12tkj-20.sch.id. (
        2026111101
        604800
        86400
        2419200
        604800
)
@       IN  NS  ns1.ukom12tkj-20.sch.id.
@       IN  A   10.10.20.2
ns1     IN  A   10.10.20.2
www     IN  A   10.10.20.2

Catatan: setiap perubahan isi zona harus menaikkan serial SOA.

Opsi BIND9:

sudo nano /etc/bind/named.conf.options

Gunakan konfigurasi berikut, dengan memastikan tidak ada deklarasi
options kedua di file yang sama:

options {
    directory "/var/cache/bind";

    listen-on { 127.0.0.1; 10.10.20.2; };
    listen-on-v6 { none; };

    allow-query {
        localhost;
        10.10.20.0/28;
        192.168.20.0/24;
    };

    recursion yes;
    allow-recursion {
        localhost;
        10.10.20.0/28;
        192.168.20.0/24;
    };

    forwarders {
        8.8.8.8;
        1.1.1.1;
    };

    dnssec-validation auto;
};

Catatan: jaringan Wi-Fi ditambahkan agar klien hotspot boleh melakukan
query langsung ke BIND9 bila memang DNS HP diarahkan langsung ke Ubuntu.
Dalam rancangan yang dipakai, DNS HP diarahkan ke MikroTik 192.168.20.1.

Validasi dan restart:

sudo named-checkconf
sudo named-checkzone ukom12tkj-20.sch.id /etc/bind/db.ukom12tkj-20.sch.id
sudo systemctl restart named
sudo systemctl status named --no-pager

Tes:

dig @127.0.0.1 ukom12tkj-20.sch.id
dig @10.10.20.2 ukom12tkj-20.sch.id
dig @127.0.0.1 google.com

Domain internal harus mengarah ke 10.10.20.2.

DNS untuk hotspot:
MikroTik menjadi DNS yang diberikan ke HP. Periksa bahwa ada DNS static

Record yang dibutuhkan:
Name    : ukom12tkj-20.sch.id

DHCP network hotspot harus memberikan:

Gateway : 192.168.20.1

Periksa dengan:

DHCP hotspot sebelumnya pernah terlihat INVALID dengan pesan
"Interface not running". Jangan membuat DHCP server kedua atau mengubah
interface sebelum memeriksa status wireless dan DHCP terkini.
Pastikan hanya ada satu DHCP server untuk jaringan hotspot.
Pool hotspot yang pernah terlihat: 192.168.20.2-192.168.20.254.

Hotspot sebelumnya terlihat menggunakan:
Interface : WLAN 1 HOTSPOT
Pool      : hs-pool-7
Profile   : hsprof1

Jangan membuat bridge baru jika rancangan tetap menggunakan WLAN
langsung sebagai interface hotspot.

Firewall:
- Jika chain forward tidak memiliki aturan drop yang memblokir trafik,
  tidak perlu menambah aturan allow yang sama berulang kali.
- Jika ada aturan drop, aturan allow dari 192.168.20.0/24 ke
  10.10.20.2 TCP port 80 harus berada sebelum aturan drop terkait.
- Untuk DNS, HP mengakses MikroTik di 192.168.20.1 port 53.
- Jangan menghapus dynamic Hotspot firewall rules.
- NAT internet yang diperlukan adalah masquerade menuju interface WAN
  ETH 1ISP. Pastikan aturan yang ada sudah bekerja sebelum menambah lagi.

10. FIREWALL UBUNTU (UFW) - JANGAN AKTIFKAN SEMBARANGAN
============================================================

Periksa dahulu:

sudo ufw status verbose

Jika UFW inactive, tidak perlu mengaktifkannya hanya untuk mengikuti
catatan. Jika UFW active dan akses layanan diblokir, izinkan layanan
untuk jaringan lab berikut:

sudo ufw allow from 10.10.20.0/28 to 10.10.20.2 port 53 proto udp
sudo ufw allow from 10.10.20.0/28 to 10.10.20.2 port 53 proto tcp
sudo ufw allow from 192.168.20.0/24 to 10.10.20.2 port 53 proto udp
sudo ufw allow from 192.168.20.0/24 to 10.10.20.2 port 53 proto tcp
sudo ufw allow from 10.10.20.0/28 to 10.10.20.2 port 80 proto tcp
sudo ufw allow from 192.168.20.0/24 to 10.10.20.2 port 80 proto tcp

Port 443 hanya diperlukan jika HTTPS benar-benar dikonfigurasi.
Jangan mengaktifkan UFW melalui SSH sebelum aturan SSH dipastikan aman.
